# Data model

PostgreSQL 17 with PostGIS 3.7. The schema is managed by Alembic
(`backend/alembic/versions/0001_initial_schema.py`). The models are in `backend/app/models.py`,
and `alembic check` confirms that models and migrations match.

Conventions:

- **Geometries are EPSG:4326** (WGS 84, longitude/latitude). PostGIS rejects other SRIDs.
- **Timestamps are `timestamptz`** (UTC), not naive `timestamp` as in the original specification,
  to avoid time-zone ambiguity.
- Status and type columns are `varchar` with `CHECK` constraints listing the allowed values.
- Ids are UUIDs generated by the application.

## images

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| filename | varchar(255) | Sanitised display name. Never used in paths or keys. |
| object_key | varchar(512) unique | `images/<id>/original.tif` |
| content_type | varchar(100) | |
| file_size | bigint | `> 0` |
| width, height | integer | `> 0` |
| crs | varchar(64) | `EPSG:<code>` or `CUSTOM` |
| resolution_x, resolution_y | double | Pixel size in source CRS units (unit in `metadata.crs_units`) |
| bounds | geometry(Polygon, 4326) | Footprint, densified so reprojected edges stay accurate. GiST index. |
| acquisition_date | timestamptz null | Only from explicit acquisition tags |
| uploaded_at | timestamptz | Default `now()`. B-tree index. |
| processing_status | varchar(20) | `UPLOADED`, `PROCESSING`, `READY`, `FAILED` |
| metadata | jsonb | Bands, dtypes, NoData, colour interpretation, native bounds, WKT, tags, COG and preview keys, display bands and ranges |

## analysis_jobs

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | Also the Celery task id |
| image_id | uuid FK → images ON DELETE CASCADE | Indexed |
| job_type | varchar(50) | `object_detection` |
| status | varchar(20) | `PENDING`, `QUEUED`, `RUNNING`, `COMPLETED`, `FAILED`, `CANCELLED`. Index on (status, created_at). |
| progress | integer | `0–100` |
| status_message | varchar(255) null | Human-readable progress, e.g. "Processing image tiles (4/9)". Not in the original specification; added for the job API. |
| model_name, model_version | varchar null | e.g. `yolo26s-obb`, `sha256:38dbd72ef680` |
| parameters | jsonb | Request, tiling parameters, worker id, run statistics |
| error_message | text null | |
| created_at, started_at, completed_at | timestamptz | |

## detections

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| image_id | uuid FK → images ON DELETE CASCADE | Index on (image_id, class_name) |
| job_id | uuid FK → analysis_jobs ON DELETE CASCADE | Indexed |
| class_name, class_id | varchar, integer | Model class |
| confidence | double | `0–1` (CHECK) |
| pixel_bbox | jsonb | `{"points": [[col, row] × 4], "clipped_to_image": bool}`: the model's oriented box in full-image pixels |
| geometry | geometry(Polygon, 4326) | Oriented box clipped to the image extent. GiST index. |
| created_at | timestamptz | |

Detections of a job are replaced atomically when the job runs (idempotent re-runs).

## Not implemented

`change_detections` from the specification is not created, because change detection is not
implemented. It will be added in a new migration when that feature exists.

## Common queries

Detections intersecting a bounding box use the GiST index (this is tested with `EXPLAIN`):

```sql
SELECT * FROM detections
WHERE ST_Intersects(geometry, ST_MakeEnvelope(-118.42, 33.93, -118.40, 33.95, 4326));
```

Latest completed detection job per image (used by the map and the statistics):

```sql
SELECT DISTINCT ON (image_id) id FROM analysis_jobs
WHERE status = 'COMPLETED' AND job_type = 'object_detection'
ORDER BY image_id, completed_at DESC;
```

## Migrations

```bash
make migrate                                  # upgrade the dev database to head
cd backend && ../.venv/bin/alembic check      # verify that models and migrations match
```

The migration requires the PostGIS extension and checks for it. Creating the extension needs a
superuser, and the application role is deliberately not one. The test suite migrates
`satellite_detection_test` down to base and up to head on every run, and refuses to run against a database
whose name does not end in `_test`.
